## Notes for later tasks

- **Deprecation warning**: `fastapi.testclient` currently uses `httpx`
  under the hood via Starlette, and Starlette 0.4x+ emits
  `StarletteDeprecationWarning: Using httpx with starlette.testclient is
  deprecated; install httpx2 instead.` This is a warning, not a failure, and
  came from the exact dependency versions the brief specified
  (`fastapi>=0.115`, `httpx>=0.28` resolved to fastapi 0.121-ish /
  starlette latest / httpx 0.28.x at install time). Later tasks doing more
  HTTP-client-heavy testing may want to watch for this; no action taken here
  since the brief pinned only lower bounds and did not ask for `httpx2`.
- **`backend/.venv` location**: created with `py -3.12 -m venv .venv` from
  inside `backend/`, using the newly-installed system Python 3.12.10
  (`C:\Users\maxim\AppData\Local\Programs\Python\Python312\python.exe`, also
  reachable as `py -3.12`). Later tasks/agents on this machine should use
  `backend/.venv/Scripts/python.exe` (or activate the venv) rather than
  assuming a bare `python`/`python3` on PATH resolves to 3.12 — the default
  `python3`/`python` still resolve to the pre-existing 3.9.13 install.
  `pip install -e ".[dev]"` from `backend/` populated it fully; SQLAlchemy,
  Alembic, argon2-cffi, PyJWT, cryptography, python-multipart,
  charset-normalizer are all installed and importable but currently unused
  (reserved for `app/db.py`, `app/models/`, `app/api/` in later tasks per
  the task context).
- **`api` router**: `app/main.py` defines `api = APIRouter(prefix="/api")`
  at module scope and mounts it with `app.include_router(api)` immediately
  after defining `/health` on it. Later tasks that need to add more routes
  to the same router should import `api` from `app.main` and call
  `api.include_router(...)` or `@api.get/post/...` **before** the module's
  own `app.include_router(api)` call executes — since Python runs
  `main.py` top-to-bottom on import, routers registered on `api` after
  import time (e.g. from a router imported inside `main.py` before the
  `include_router` line) need to be wired in before that line, not after.
  Simplest pattern: import and attach sub-routers to `api` in `main.py`
  before `app.include_router(api)`, as the task context implies.
- No SPA catch-all was added, per instructions (reserved for Task 21).
- `.env` is read by `Settings` (`env_file=".env"`) but no `backend/.env`
  file was created — `secret_key` and other values fall back to their
  insecure dev defaults, which is expected/documented behavior at this
  stage (no `.env.example` was requested by the brief either).
