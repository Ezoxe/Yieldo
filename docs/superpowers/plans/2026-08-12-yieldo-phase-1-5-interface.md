# Yieldo Phase 1.5 — Interface : Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Make Yieldo look like a product someone chose to use, and fix the four usability defects the operator hit on first deploy.

**Why this phase exists:** phase 1 shipped 435 passing tests and a rejected interface. Every frontend test ran in jsdom, which has no rendering engine, so 23 tasks and 24 reviews confirmed components mounted and never once saw the screen. The liquid glass, the mesh background and the staggered motion specified in the design doc are all present in the code and invisible in the browser.

**The rule that governs this phase:** no task is done until someone has opened it in a browser, at 375px / 768px / 1440px, in both themes, with the operator's real data volumes — and attached the screenshots to the report. A passing test proves nothing about how this looks.

## Design system

Authoritative reference: `design-system/yieldo/MASTER.md`, generated by the `ui-ux-pro-max` skill. Read it before touching any component.

Resolved direction, combining the skill's recommendations with the operator's decision to keep the existing accent:

- **Structure: Bento Grids.** Cards of deliberately varying size, not a uniform stack. Hierarchy comes from area, not from font weight.
- **Palette: Abysse teal retained.** Accent `#7ee2d6`, positive `#4fd6a8`, negative `#e5606b`, warning `#f4a261`, info `#3b82f6`. Light-theme variants already clear WCAG AA and `frontend/src/design/contrast.test.ts` enforces it from disk — keep it green.
- **Depth:** never pure black. Base gradient from `#0a1622` to `#050c14`. Two or three absolutely-positioned ambient blobs, teal-tinted, blur 30-50px, opacity 0.08-0.12, oscillating slowly.
- **Surfaces:** radius 16px, hairline `rgba(255,255,255,0.08)` borders, never solid grey. Real `backdrop-filter` on floating surfaces; data surfaces stay opaque.
- **Motion:** signature easing `cubic-bezier(0.16, 1, 0.3, 1)`. Entry stagger on cards, animated counters on figures, shared-element route transitions. Everything gated behind `useReducedMotion()`, which already reads both the media query and the user's own switch.
- **Typography:** keep Geist for text; Geist Mono tabular for every figure. The skill suggested Fira — rejected, since the existing pairing is already correct for data and swapping fonts is not what makes this look better.
- **Explicitly avoid:** playful styling, AI-style purple/pink gradients, emoji as icons.

## Global Constraints

- Code, identifiers, comments and commit messages in English; all user-facing text in French.
- Amounts are integer cents; only `formatCents` / `formatCompactCents` convert for display.
- Colours come from `tokens.css` custom properties. No hard-coded hex in a component — `contrast.test.ts` guards the palette and must stay green.
- `prefers-reduced-motion` and the in-app animation switch both respected everywhere.
- No silent failures.
- Conventional Commits, one commit per task.
- Backend currently 220 tests, frontend 215. Both stay green.

## Task 1 — Visual foundations

Atmospheric background layer (gradient plus animated ambient blobs, disabled under reduced motion), the bento grid primitives, the signature easing token, and motion primitives for card entry and figure counting. Extend `tokens.css` rather than replacing it.

Deliverable: a demo route rendering the primitives, screenshotted at three widths in both themes.

## Task 2 — Public landing page

Route `/` when unauthenticated, following the skill's "Real-Time / Operations Landing" pattern: hero with a live product preview, key capabilities, how it works, call to action. In French. States plainly what Yieldo does and does not do — it is not a bank aggregator, nothing leaves the machine. Authenticated users still land on the dashboard.

## Task 3 — Dashboard in bento

Rebuild `OverviewPage` on the bento grid: the net figure gets the largest cell, cashflow next, then treemap, calendar and stat tiles at varying sizes. Animated counters. Staggered entry. The charts already exist — this is layout, depth and motion, not new charts.

## Task 4 — Transactions and import screens

Same treatment. In the import wizard, the commit button becomes a floating action bar pinned to the viewport — the operator missed it entirely because it sat below a preview table hundreds of rows long, imported nothing, and concluded his data had vanished.

## Task 5 — The four usability defects

1. **Signed amount column preferred.** `suggest_mapping` proposes separate Débit/Crédit roles when a French bank export normally ships one signed column with negatives and positives mixed. Detect the single-signed-column shape and propose `amount`. Both remain user-overridable.
2. **"Tout" means all.** The client sends no dates, and the backend's `_default_range` then applies the current calendar year, so older history stays invisible. Verified live: `GET /api/analytics/summary` returned `date_from: 2026-01-01`.
3. **Import history visible.** `GET /api/imports` exists and no screen calls it. Show past batches with their counts and the rollback action.
4. **Empty states that diagnose.** "Aucune transaction sur cette période" while data exists outside the period is actively misleading — say so, and offer to widen the range.

## Task 6 — Browser verification pass

Walk the full journey in a browser against the deployed instance with real data. Screenshots at 375, 768 and 1440, both themes, reduced-motion on and off. Anything that looks wrong is a finding, not a matter of taste.
